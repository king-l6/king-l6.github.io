DevPilot:给 AI 面试助手加上 token 计量

DevPilot 是个基于 Next.js 的 AI 面试助手。这次主要给它加了 token 计量:后端按 requestId 存下每次对话的 token 用量,前端展示总用量和每条消息各自的消耗。做 AI 应用,成本可见很重要。

为什么要按 requestId

一次对话往往是多轮流式返回,如果只在最后记一个总数,就没法回溯是哪条消息贵。所以用 requestId 关联一次请求,把 usage 挂在这个 id 下,前端就能一条条对上。

消息格式的坑

useChat 返回的消息结构和 streamText 期望的输入结构不完全一致,中间要做一层转换,否则多轮上下文会对不上。这个转换错了不会报错,只会表现为"模型好像忘了前面说过什么",排查花了些时间。最后靠打印每一轮实际发出去的 messages 才定位到。

结论:做流式 AI 应用,一定要有办法看到"真正发给模型的完整 payload"。前端展示的和实际发送的经常不是一回事。
