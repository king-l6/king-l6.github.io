GitHub 每周最火榜:一次 CI 踩坑记

做了个 GitHub 每周最火项目榜:抓热门仓库,按 star 的日增速排序,英文描述自动翻成中文。功能不复杂,但上线时被 CI 折腾得够呛,这篇主要记踩的坑。

坑一:npm 在 runner 上崩溃

CI 里 npm install 直接崩,本地却好好的。试了几轮,最后干脆把包管理换成 pnpm,绕开了 npm 在那个 runner 环境上的问题。有时候不必死磕一个工具的偶发 bug,换条路更快。

坑二:内网私服

项目里的 .npmrc 指向了公司内网私服,CI 在公网环境根本连不上,一直卡在拉依赖。把 .npmrc 改回公共 registry 才通。这种配置泄漏到公开项目里是个常见坑,提交前该检查一下 .npmrc 和 lockfile 里的源。

坑三:构建缓存进了 git

tsconfig.tsbuildinfo 这个增量构建缓存被误提交了,导致 CI 上构建行为和本地不一致。加进 .gitignore、停止追踪之后正常。

小结:CI 的问题大多不是代码本身,而是环境差异——包管理器、registry、被误提交的缓存。排查思路就是不断缩小"本地和 CI 到底哪里不一样"。
